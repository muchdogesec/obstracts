# CTI Butler

## Product purpose and users

CTI Butler is a structured retrieval and interoperability layer for major cyber
threat-intelligence knowledge bases. It unifies ATT&CK, CAPEC, CWE, ATLAS,
DISARM, D3FEND, locations, sectors and related datasets, connects their STIX
objects, and exposes them through search, REST, TAXII, MCP, STIX, and Navigator
outputs. It provides context to existing CTI workflows; it is not a replacement
TIP.

Primary users are CTI analysts, detection/hunting teams, security engineers,
developers, and AI agents that need grounded, structured CTI retrieval.

## Repositories

| Repository | Owns |
| --- | --- |
| `ctibutler` | Knowledge-base ingestion, version selection, relationship processing, graph search and core REST API |
| `ctibutler_web_be` | Hosted users/teams/plans, product proxy/search API, MCP/TAXII, schemas and sitemaps |
| `ctibutler_web_fe` | Unified search, knowledge-base/object detail, integrations and team workflows |
| `ctibutler_web_deploy` | Production services, Nginx routes, backups and deployment |

## Data path

1. Source-specific generator or mirror workflows publish versioned STIX bundles
   under `downloads.ctibutler.com`.
2. Core jobs download a selected version and use `stix2arango` to store it in
   the knowledge base's ArangoDB collection.
3. `arango_cti_processor` creates cross-framework relationships and groupings;
   core also creates collection-specific relationships such as technique/tactic
   links.
4. Core search and object endpoints expose the combined graph.
5. The web backend adds hosted authorization, team/plans/API keys, MCP/TAXII,
   public schemas, and presentation/proxy behavior.

Current bundle sources include ATT&CK Enterprise/ICS/Mobile, CAPEC, CWE, ATLAS,
DISARM, D3FEND, F3, CLOAK, locations, and sectors. Some are generated by local
`*2stix` repositories; others are mirrored/transformed upstream datasets.

## Developer ownership guide

- Dataset-specific mapping/generation: the matching generator repository such
  as `cwe2stix`, `location2stix`, `sectors2stix`, `disarm2stix`,
  `d3f3nd2stix`, or `cloak2stix`.
- Cross-knowledge-base relationship rules: `arango_cti_processor`.
- Import/version jobs, unified graph queries/search and core endpoints:
  `ctibutler`.
- Hosted authorization, subscriptions, MCP/TAXII, and proxy behavior:
  `ctibutler_web_be` and possibly `web_commons`.
- Browser search/object workflows: `ctibutler_web_fe`.
- Routing/containers/backups: `ctibutler_web_deploy`.

## Important code surfaces

- Core routes: `ctibutler/urls.py`; imports/processors:
  `ctibutler/worker/tasks.py`; dataset views under `ctibutler/server/views/`.
- Web routes: `project/urls.py`; product proxy API: `ctibutler_api/`; MCP:
  `ctibutler_mcp/`; team extensions: `ctibutler_teams/`.
- Frontend routes center on `/search`, `/knowledgebases/[attackType]`, object
  detail, `/integrations`, and teams.

## Validation focus

Test dataset version discovery/import, source collection selection, object
version and `_is_latest` semantics, cross-framework edges, embedded relations,
search relevance, downstream lookups, team/API-key access, and output parity
across REST/MCP/TAXII/STIX/Navigator.

## Supporting repositories
